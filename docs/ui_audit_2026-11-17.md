# 部署验收与前端体验评审（2026-11-17）

对象：`http://10.51.13.7:8020`（nginx → api → vision + ocr），版本 v5.1.0。
方法：真实 HTTP 探测 + 真实图片推理 + 无头 Chrome 逐页点检（桌面 1440 / 平板 1024 / 手机 390）。

## 1. 结论

服务本体是健康的：接口契约、真实推理、下游就绪、错误码都正常，单图 0.5–0.9s。
问题集中在两处：

1. **打包/换机后的绝对路径失效**，让「快速标注」整页图片 403、评测队列被静默丢弃；
2. **前端没有响应式，也缺少加载/空/错误三态**，所以手机端布局直接塌，桌面端识别页半边空白。

这两类都已经在本仓库改掉，并补了回归测试；重新构建 `api` 镜像即可生效。

## 3. 问题清单（按影响排序）

### P0 快速标注整页不可用：历史绝对路径失效

`var/feedback.sqlite3` 的 42 条标注、`data/processed/relabel_plan.json` 的 74 条计划、
`docs/reports/verified_oof.json` 的 1306 条预测路径，全部写死成导出机器的
`/Users/deepway/data/spmcv/...`；容器里 `ROOT=/app`，`_safe()` 直接 403。

连锁后果：

- 标注页 24 张待复核图全部 403；
- `review_queue` 用 `Path(path).is_file()` 过滤，换机后 OOF 候选被**静默全部丢弃**，
  线上队列只剩上传批次（而且上传批次也是同一个坏前缀）；
- 复核过的图路径换算后与库里的记录对不上，会反复回到队列。

修法：`app/api/viz.py` 增加 `_portable()`，把任意绝对路径按后缀重新挂到当前 `ROOT`
（`/Users/.../data/raw/recut/x.jpg` 与 `/app/data/raw/recut/x.jpg` 都能解析），
白名单校验保持不变；`review_queue` 的「已复核集合」也先归一化再比较，并返回
`missing` 计数供前端提示。

### P1 `/metrics` 不是 Prometheus 文本

`return metrics.render()` 被 FastAPI 当 JSON 字符串序列化，`Content-Type: application/json`。
抓取端拿到的是 `"# TYPE ...\n..."`。已改为 `PlainTextResponse(text/plain; version=0.0.4)`，
并加了契约测试。

### P1 手机端布局崩

没有任何 `@media`，`.shell` 固定 `216px + 1fr`。390px 视口下实际排版宽度 956px：
侧边栏占 216px、KPI 被裁、柱状图挤成 100px 宽的竖排文字、服务状态卡挤成一列单字。
已做：抽屉式导航（☰ + 遮罩 + Esc/点击关闭）、KPI 2 列、单列卡片、表格横向滚动、
命中区 ≥40px；柱状图在窄屏改成 12 行条形列表（缩放后的 SVG 文字只有 4px，读不了）。

### P2 在线识别页「信息密度」问题

- 未选图时右栏 554px 全空（`.infer-right:empty{display:none}` 让左栏只占 1.1fr）；
- 后端支持 `expected_plate` / `expected_odometer` / `axle_type` / `expected_action` /
  `expected_vin`，**前端一个入口都没有**，工单比对能力等于没上线；
- 只有一句「识别中…」的纯文本，没有耗时/进度/重试；失败也只有一行 `失败：…`。

已改：参数区（按三类照片切换字段）、结果区空态说明、骨架+计时进度、失败卡带
`request_id` 与重试/复制、结论横幅（可自动通过 / 需人工复核 + 首条原因）、
「复制结果 JSON」方便对接上层。

### P2 错误样本一次渲染 35 张 → 6708px 长页

现在每页 24 张 + 「加载更多（还有 N 张）」，页脚常驻「已选 x / 共 y」；
「全选本组」从只作用于已渲染卡片改为真正整组。

### P3 其它

- 总览柱状图橙色（<70%）没有图例，也没有整体参照线 → 加图例、虚线参照、口径说明；
- KPI 只有静态评测数，看不到线上延迟 → 新增「服务运行指标」（P50/P95/请求/复核率/错误数）；
- 空列表、未加载状态一律是 `加载中…` 一行字 → 统一骨架屏 + 空态组件；
- 图片 403 时浏览器留 300px 黑块 → 统一「图片不可用」占位，并统计缺失数提示；
- 模型版本表里 `v5.0.0 95.33%（单折 107 张）` 与当前 `87.09%（5 折 OOF）` 并排，
  容易被误读成旧版更好 → 加「不可比」标签；
- `alert()` 换成页内 toast；补 `alt`、skip link、`aria-current`、`aria-live`；
- `#out` / 视图加 `scroll-margin-top`，程序化滚动不再被吸顶栏盖住结论。

### 数据与部署侧的观察

- 线上有 4 个内容相同的测试批次（`upload_20261116_1409/1537xx`，各 20 张同一批图），
  标注队列里表现为大量重复；前端已按文件名去重，但**接口没有删除批次的能力**，建议补；
- 模型页残留一次 `epoch 1/1, top1 100%` 的测试训练记录和「注册为候选版本」按钮，
  生产环境看着像真结果，建议清掉 `var/train_jobs` 相关状态；
- `Dockerfile.api` 用 `--workers 2`，但准入信号量、限流桶、`/metrics` 都是**进程内状态**：
  实际并发上限是 8×2，限流是 120×2，`/metrics` 每次只反映随机一个 worker。
  建议二选一：单 worker（让 8 并发/120 rpm 名副其实），或在 nginx/网关层限流；
- `/sso/config` 的 `views` 只映射了 6 个页面，缺 `label`、`model`，一旦打开 SSO，
  这两页会按原始名字 `label`/`model` 去匹配菜单码，容易被挡；
- SSO 当前关闭（`enabled:false`），`/sso/config` 会直接返回 appCode/poolCode；
  内网可接受，开放前建议按需要收敛。

## 5. 复核方法

```bash
# 1. 本地起服务（需要 vision/ocr 在 8016/8018）
python -m uvicorn app.main:app --port 8017

# 2. 单元 + 浏览器回归（10 步全绿）
make test
BASE=http://127.0.0.1:8017 node tools/ui_smoke.mjs

# 3. 线上重新部署后
curl -sI  http://10.51.13.7:8020/metrics | grep -i content-type   # text/plain
curl -s   http://10.51.13.7:8020/viz/api/review_queue?family=oil | jq '{total,missing,done}'
```

部署注意：`web/` 是 `COPY` 进 api 镜像的，改前端必须重建 api；
nginx 改完用 `docker exec <nginx> nginx -t` 或直接 `docker compose restart nginx` 验证。
