# SPM 功能验收接口

**推荐：一个接口 + `scene` 参数。** 上层只判断 HTTP 状态码：

| HTTP | 含义 | 上层动作 |
|---|---|---|
| **200** | **该场景需求满足** | 放行 |
| **422** | **需求不满足**（`message` 写原因，`missing` 列缺的照片） | 转人工/补拍 |
| 400 / 413 | 请求本身有问题 | 修请求后重试 |
| 5xx | 服务异常 | 重试 |

响应体里**没有 `ok`、没有 `result`、没有 `codes`、没有 `boxes`**。
通过/不通过就是 HTTP 状态码；`message` 给人看，`data` 给业务取识别结果。

## 为什么一个接口 + scene 最好

- 上层只维护一个 URL、一套超时/重试/日志，不需要按三个路径分别适配；
- 请求/响应结构完全统一，场景差异只在 `data` 的字段和可选参数；
- 新增场景只加一个 `scene` 枚举值，不新增路由、不改 SDK；
- 三个接口只是把 `scene` 从参数挪到路径，收益很小，却要维护三份文档、三套参数和三套错误处理。

如果调用方团队坚持按路径分流，另外保留了三个**完全等价**的别名（同一份实现，返回一模一样）：

```text
POST /v1/check/arrival
POST /v1/check/repair
POST /v1/check/inspection
```

## 1. 请求

```http
POST http://10.51.13.7:8020/v1/check
Content-Type: multipart/form-data
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scene` | string | 是 | `arrival` / `repair` / `inspection` |
| `images` | file[] | 是 | 该场景的全部照片 |
| `axle_type` | string | 否 | 仅 repair：`hande`=汉德桥，其它或留空=非汉德桥 |
| `expected_plate` | string | 否 | 仅 arrival：工单车牌，传了且识别到才比对 |
| `expected_vin` | string | 否 | arrival / inspection：工单 VIN，传了才比对 |
| `expected_odometer` | number | 否 | 仅 arrival：工单里程，传了且识别到才比对，误差 >5% 不通过 |

`expected_*` 不传时只校验照片齐全和识别结果自身（例如两个 VIN 是否一致）；
**要和工单核对，必须传对应的期望值。**

> 特别是 VIN：不传 `expected_vin` 时，检查表只校验“有 VIN”，读错字（如 `H`→`A`）也可能返回 200。
> 生产联调请务必传 `expected_vin`。

## 2. 响应

### 通过（HTTP 200）

```json
{
  "scene": "arrival",
  "message": "接车照片满足需求：四类照片齐全，VIN 校验通过",
  "missing": [],
  "data": {
    "plate": "晋D08906D",
    "vin": "HLC3J2VF9TA604594",
    "odometer": 182
  }
}
```

### 不通过（HTTP 422）

```json
{
  "scene": "repair",
  "message": "缺少照片：桥加油",
  "missing": ["桥加油"],
  "data": {
    "axle": "drain",
    "tire": "drain+fill",
    "filter": null
  }
}
```

公共字段：

| 字段 | 说明 |
|---|---|
| `scene` | 本次验收的场景 |
| `message` | 一句话结论/原因，可直接给现场或业务看 |
| `missing` | 缺少的照片类型（中文），通过时为空数组 |
| `data` | 该场景的识别结果，字段见下表；没识别到的值为 `null` / `false` |

### `data` 按场景返回

| 场景 | 字段 | 值 |
|---|---|---|
| `arrival` | `plate` | 车牌，未识别为 `null` |
| | `vin` | 采信的 VIN；两个 VIN 都读到且一致才有值，否则 `null` |
| | `odometer` | 里程读数，未识别为 `null` |
| `repair` | `axle` | 桥的动作：`drain` / `fill` / `drain+fill` / `null` |
| | `tire` | 轮胎的动作：`drain` / `fill` / `drain+fill` / `null` |
| | `filter` | 滤芯状态：`none` / `has` / `none+has` / `null` |
| `inspection` | `vin` | 首页完整 VIN，未读到为 `null` |
| | `vin_partial` | 只读到尾段时给尾段，否则 `null` |
| | `signature` | 是否检测到客户签字 |
| | `stamp` | 是否检测到服务站盖章 |

说明：非汉德桥不判滤芯，`repair.data.filter` 固定为 `null`；汉德桥不判轮胎，`tire` 固定为 `null`。

## 3. 需求对照（来自 `SPM系统AI识别.xlsx`）

### 3.1 接车 `scene=arrival`

| 照片/检查 | 判定 |
|---|---|
| 车头及车牌 | 必须有车头照片；车牌读不到时**按规格跳过**车牌校验；读到且传了 `expected_plate` 才比对 |
| 行驶证 VIN、车架 VIN | 两张照片都要有；**至少读到一个 VIN**；两个都读到必须一致；传了 `expected_vin` 才与工单比对 |
| 里程表 | 必须有里程表照片；读出里程且传了 `expected_odometer` 才做 ±5% 比对；读不出里程不算失败 |

### 3.2 维修 `scene=repair`

| 桥型 | 必须有的照片 | 不判 |
|---|---|---|
| 非汉德（`axle_type` 留空或其它） | 桥放油、桥加油、轮胎放油、轮胎加油 | 滤芯（上传了也忽略，不判失败） |
| 汉德（`axle_type=hande`） | 桥加油、无滤芯、有滤芯 | 轮胎（上传了也忽略，不判失败） |

照片存在但动作没判定出来，也算不满足；拍错场景导致缺项，直接返回缺少哪一类。

### 3.3 检查表 `scene=inspection`

| 照片/检查 | 判定 |
|---|---|
| 服务单首页 | 必须有；VIN 要能读到。完整 VIN 直接比对；只有尾段时，传了 `expected_vin` 且尾段能对上才算通过 |
| 服务单末页 | 必须有；客户签字、服务站盖章都要检测到 |
| 工单 VIN | 传了 `expected_vin` 才比对；不传只校验 VIN 是否存在 |

## 4. 调用示例

```bash
# 接车
curl -X POST http://10.51.13.7:8020/v1/check \
  -F "scene=arrival" \
  -F "images=@plate.jpg" \
  -F "images=@license.jpg" \
  -F "images=@frame.jpg" \
  -F "images=@odometer.jpg" \
  -F "expected_plate=晋D08906D" \
  -F "expected_vin=HLC3J2VF9TA604594" \
  -F "expected_odometer=182"

# 维修：汉德桥
curl -X POST http://10.51.13.7:8020/v1/check \
  -F "scene=repair" -F "axle_type=hande" \
  -F "images=@axle_fill.jpg" -F "images=@filter_none.jpg" -F "images=@filter_has.jpg"

# 检查表
curl -X POST http://10.51.13.7:8020/v1/check \
  -F "scene=inspection" \
  -F "images=@front.jpg" -F "images=@sign.jpg" \
  -F "expected_vin=HLC3J2V13TA603182"
```

```python
import requests

files = [("images", open(p, "rb")) for p in ["plate.jpg", "license.jpg", "frame.jpg", "odometer.jpg"]]
r = requests.post(
    "http://10.51.13.7:8020/v1/check",
    files=files,
    data={"scene": "arrival", "expected_plate": "晋D08906D",
          "expected_vin": "HLC3J2VF9TA604594", "expected_odometer": "182"},
    timeout=60,
)
if r.status_code == 200:
    print("通过", r.json()["data"])
else:
    print("不通过：", r.json()["message"], r.json()["missing"])
```

## 5. 错误响应

错误也返回同一结构，通过 `scene` / `message` / `missing` / `data` 四个字段：

```json
{
  "scene": "arrival",
  "message": "缺少 images 图片",
  "missing": [],
  "data": {}
}
```

| HTTP | 场景 |
|---|---|
| 400 | 没传 `images`、图片为空或格式不支持 |
| 413 | 单张 >15MB 或总量 >80MB |
| 422 | `scene` 不合法、`expected_odometer` 不是数字，或**需求不满足** |
| 500 | 内部异常，可重试 |

## 6. 和旧接口的关系

`/v1/arrival`、`/v1/repair`、`/v1/inspection`、`/v1/scan`、`/v1/workorder`、`/v1/analyze`
保留给控制台/内部排查，**上层业务只接 `/v1/check`**。
