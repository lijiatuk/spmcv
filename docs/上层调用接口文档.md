## 1. 接口概述

上传现场照片，返回识别场景与结构化字段。

| 接口 | 功能 |
|---|---|
| `POST /v1/arrival` | 接车照片：车牌、行驶证 VIN、车架 VIN、里程 |
| `POST /v1/repair` | 维修照片：桥/轮胎加油放油、有无滤芯 |
| `POST /v1/inspection` | 检查表照片：首页 VIN、末页签字与盖章 |

三个接口按场景拆分，请求方式一致，响应在公共字段（`result`/`codes`/`photos`）之外各带本场景字段。另有 `/v1/workorder`（整单校验）、`/v1/scan`（统一入口），见第 4 节。

## 2. 请求说明

- 请求地址：`http://10.51.13.7:8020/v1/{arrival|repair|inspection}`
- 请求方法：`POST`
- Content-Type：`multipart/form-data`
- 参数位置：除 `boxes` 外，表里的参数都是 **multipart 表单字段**；`boxes` 是 **URL query 参数**，必须写成 `POST /v1/arrival?boxes=1`，放在表单里不会生效。
- 认证：当前未开启；开启后请求头带 `X-API-Key`
- 追踪：可选请求头 `X-Request-Id`，响应头原样返回
- 图片格式：jpeg / png / webp / tiff
- 限制：单张 ≤ 15MB，单请求 ≤ 80MB、≤ 20 张；默认 120 次/分，并发 8，超限返回 `429`

**公共请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `images` | file[] | 是 | 图片，可多张同名上传 |

**响应约定**

- 业务结果在响应体中，HTTP 200 不代表业务通过。
- 业务结论只有一个字段 `result`：`pass`（可自动通过）、`partial`（照片不齐，仅 arrival）、`review`（需人工）。`/v1/meta` 的 `version` ≥ 2.1 才有该字段，旧版返回的是 `ok`/`status`。
- `codes` 为机器可读原因码，`reasons` 为对应中文说明；`missing_reasons` 是「没交这类照片」的中文说明，只在 arrival 返回。
- `result=pass` 是规则结论，**不代表逐图都可信**：维修类低置信、`expected_action` 不一致等只写在 `photos[].need_review` / `photos[].review_reasons`，当前不改变顶层 `result`。自动放行前要同时检查逐图标记。
- `/v1/scan` 不传 `category` 时只做场景识别，固定返回 `result="review"`、`codes=["CATEGORY_REQUIRED"]`；要业务结论必须传 `category`。

## 3. 接口详情

### 3.1 接车识别 `POST /v1/arrival`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `images` | file[] | 是 | 车头、行驶证、车架铭牌、里程表照片 |
| `expected_plate` | string | 否 | 工单车牌，识别到则比对 |
| `expected_odometer` | number | 否 | 工单里程，误差 >5% 判不符 |
| `strict` | bool | 否 | `1` 时照片不齐判不通过，默认只校验已上传照片 |
| `boxes` | bool | 否 | **query** 参数；`?boxes=1` 时逐图返回检测框坐标 |

**响应参数**

| 字段 | 类型 | 说明 |
|---|---|---|
| `result` | string | `pass` 齐全一致 / `partial` 照片不齐 / `review` 需人工 |
| `complete` | bool | 四类照片是否齐全且 VIN 一致 |
| `plate` | string | 车牌 |
| `vin` | object | `license`、`frame`、`match`（两个 VIN 是否一致）、`license_unverified`/`frame_unverified`（校验位不过的原始读数） |
| `odometer` | number | 里程读数 |
| `present` | string[] | 已识别的场景 |
| `missing_scenes` | string[] | 未上传的场景 |
| `missing_reasons` | string[] | 未上传场景的中文说明，如 `未提交行驶证照片` |
| `reasons` | string[] | 不通过原因 |
| `hints` | string[] | 不阻断提示 |
| `photos` | object[] | 逐图结果，见 3.4 |
| `unexpected` | object[] | 不属于本场景的图片 |
| `codes` | string[] | 原因码 |

**响应示例**

```json
{
  "category": "arrival", "result": "partial", "complete": false,
  "plate": "晋K05907D", "vin": {"license": null, "frame": null, "match": false},
  "odometer": null,
  "present": ["arrival_plate"],
  "missing_scenes": ["license_vin", "frame_vin", "odometer"],
  "missing_reasons": ["未提交行驶证照片", "未提交车架铭牌照片", "未提交里程表照片"],
  "reasons": [], "hints": [], "codes": [],
  "photos": [
    {"index": 0, "filename": "plate.jpg", "scene": "arrival_plate",
     "scene_label": "车头及车牌", "confidence": 0.9998, "model_version": "v5.1.0",
     "latency_ms": 1403, "need_review": false, "review_reasons": [], "action": null,
     "field_summary": {"plate": "晋K05907D", "vin": null, "odometer": null},
     "ocr_text": "晋K05907D"}
  ],
  "unexpected": []
}
```

### 3.2 维修识别 `POST /v1/repair`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `images` | file[] | 是 | 桥、轮胎、滤芯照片 |
| `axle_type` | string | 否 | `hande` 启用汉德桥规则 |
| `expected_action` | string | 否 | 期望动作 `drain` / `fill`，不一致写入该图 `review_reasons`（不改变顶层 `result`，调用方需自己看逐图原因） |
| `boxes` | bool | 否 | **query** 参数；`?boxes=1` 时逐图返回检测框坐标 |

**响应参数**

| 字段 | 类型 | 说明 |
|---|---|---|
| `result` | string | `pass` / `review` |
| `oil` | object | 桥与轮胎动作：`axle`/`axle_actions`/`axle_label`、`tire`/`tire_actions`/`tire_label` |
| `filter` | object | 滤芯：`state`/`actions`/`label` |
| `present` | string[] | 已识别的场景 |
| `reasons` | string[] | 不通过原因 |
| `photos` | object[] | 逐图结果，见 3.4 |
| `unexpected` | object[] | 不属于本场景的图片 |
| `codes` | string[] | 原因码 |

**响应示例**

```json
{
  "category": "repair", "result": "pass",
  "oil": {"axle": "drain", "axle_actions": ["drain"], "axle_label": "放油",
          "tire": null, "tire_actions": [], "tire_label": null},
  "filter": {"state": null, "actions": [], "label": null},
  "present": ["bridge_drain"], "reasons": [], "codes": [], "unexpected": []
}
```

示例省略 `photos[]`，结构见 3.4。

### 3.3 检查表识别 `POST /v1/inspection`

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `images` | file[] | 是 | 服务单首页、末页照片 |
| `expected_vin` | string | 否 | 期望 VIN，仅在首页读到完整 VIN 时比对；不一致返回 `SERVICE_VIN_MISMATCH` |
| `boxes` | bool | 否 | **query** 参数；`?boxes=1` 时逐图返回检测框坐标 |

**响应参数**

| 字段 | 类型 | 说明 |
|---|---|---|
| `result` | string | `pass` / `review` |
| `service_front_vin` | string | 首页完整 VIN |
| `service_front_vin_partial` | string | 仅识别到尾段时给出 |
| `signature` | bool | 是否有客户签字 |
| `stamp` | bool | 是否有服务站盖章 |
| `present` | string[] | 已识别的场景 |
| `reasons` | string[] | 不通过原因 |
| `photos` | object[] | 逐图结果，见 3.4 |
| `unexpected` | object[] | 不属于本场景的图片 |
| `codes` | string[] | 原因码 |

> 首页 VIN 读到了但**校验位不通过**时，同样返回 `review` + `VIN_CHECKSUM_FAILED`，不会因为签字盖章齐就放行。

**响应示例**

```json
{
  "category": "inspection", "result": "review",
  "service_front_vin": null, "service_front_vin_partial": "3307018",
  "signature": true, "stamp": true,
  "present": ["service_front", "service_sign"],
  "reasons": ["VIN 仅识别到尾段 3307018"], "codes": ["OTHER"], "unexpected": []
}
```

示例省略 `photos[]`，结构见 3.4。

### 3.4 逐图结果 `photos[]` / `unexpected[]`

| 字段 | 类型 | 说明 |
|---|---|---|
| `index` | int | 上传顺序，从 0 开始 |
| `filename` | string | 原文件名 |
| `scene` | string | 识别场景（12 类 slug，如 `arrival_plate` / `bridge_drain` / `filter_has`） |
| `scene_label` | string | 场景中文名（如 `桥放油` / `有滤芯`） |
| `confidence` | number | 场景置信度 |
| `model_version` | string | 模型版本 |
| `latency_ms` | int | 该图耗时 |
| `need_review` | bool | 该图是否需复核 |
| `review_reasons` | string[] | 复核原因 |
| `action` | string | 动作：`drain` / `fill` / `has` / `none` |
| `field_summary` | object | 结构化字段：`vin`、`plate`、`odometer`、`vin_partial`、`vin_checksum_ok`；另有候选值 `vin_candidates`、`plate_candidates`、`odometer_candidates`（供人工核对） |
| `ocr_text` | string | OCR 原文（≤400 字），仅用于排查 |
| `timed_out` | bool | 可选，分析超时 |
| `ocr_error_code` | string | 可选，OCR 异常码 |
| `boxes` | object[] | 可选，`?boxes=1` 时返回；元素为 `{"label":"license_plate","score":0.82,"box":[x1,y1,x2,y2]}`，坐标是原图像素 |

> `unexpected[]` 的结构与 `photos[]` 相同，表示「这张图不属于本场景」，不参与判定。
> 传错场景不会让请求失败，只会进 `unexpected`。

## 4. 其他接口

| 接口 | 用途 | 主要参数 | 通过标志 |
|---|---|---|---|
| `POST /v1/workorder` | 整单跨图校验 | `images`、`work_order_id`、`expected_vin/plate/odometer`、`axle_type` | `result="pass"` |
| `POST /v1/scan` | 统一入口 | `images`、`category`（`arrival`/`repair`/`inspection`，可空）、`expected_*` | `result="pass"` |
| `POST /v1/analyze` | 单图识别（内部排查用） | `image`（单数字段）、`axle_type`、`expected_action` 等 | 看 `need_review`，无 `result` |

`/v1/workorder` 的返回：

| 字段 | 类型 | 说明 |
|---|---|---|
| `work_order_id` | string | 原样回传 |
| `result` | string | `pass` / `review` |
| `review_reasons` / `codes` | string[] | 中文原因 / 原因码 |
| `vin` | object | `vin`（采信的完整 VIN）、`by_scene`（各图读到的 VIN）、`partials`（尾段）、`confidence`（`full`/`partial`）、`reasons` |
| `mileage` | object | `odometer`、`ok`、`reasons` |
| `plate` | string | 车牌 |
| `oil` | object | `session`（`axle_oil` / `tire_oil` 的动作数组）、`reasons` |
| `filter` | object | `states`（`has`/`none` 数组）、`reasons` |
| `service_sign` | object | `present`、`ok`、`reasons` |
| `scenes` | string[] | 本单出现过的场景 |
| `missing_scenes` | string[] | 整单要求但未提交的场景 |
| `photos` | object[] | 逐图结果，结构与 3.4 **不同**：`filename`、`scene`、`scene_confidence`、`conclusion`、`fields`、`review_reasons`、`latency_ms` |
| `latency_ms` | int | 整单耗时 |

`/v1/scan` 返回对应场景的字段（arrival 为 `complete`/`vin`/`odometer` 等，repair 为 `oil`/`filter`，inspection 为 `service_front_vin`/`signature`/`stamp`）及 `result`；`category` 留空时只返回逐图场景，固定 `result="review"`。`expected_vin` 只在 `category=inspection` 时参与比对，`strict` 只在 `category=arrival` 时生效。

## 5. 错误码

| HTTP | code | 说明 |
|---|---|---|
| 400 | `BAD_REQUEST` | 图片格式不支持或空文件 |
| 401 | `UNAUTHORIZED` | 缺少或无效 `X-API-Key`（开启认证后） |
| 413 | `PAYLOAD_TOO_LARGE` | 单张或总量超限 |
| 422 | `INVALID_PARAMS` | 参数缺失或非法 |
| 429 | `RATE_LIMITED` | 调用频率超限，按 `Retry-After` 重试 |
| 429 | `BUSY` | 并发已满，按 `Retry-After` 重试 |
| 5xx | `INTERNAL_ERROR` | 服务内部错误，可重试 |

错误响应体：

```json
{"code": "INVALID_PARAMS", "message": "参数校验失败", "request_id": "ae12...", "path": "/v1/arrival"}
```

参数校验失败（422）时还会带 `errors[]`（FastAPI 原始校验明细），排查时可用，业务分支只看 `code`。

**业务原因码 `codes`**

| code | 说明 |
|---|---|
| `MISSING_PLATE` / `MISSING_LICENSE_VIN` / `MISSING_FRAME_VIN` / `MISSING_ODOMETER` | 已上传照片但字段未识别 |
| `VIN_MISMATCH` / `PLATE_MISMATCH` / `ODOMETER_MISMATCH` | 识别结果与工单不一致 |
| `VIN_CHECKSUM_FAILED` | VIN 校验位不通过 |
| `MISSING_DRAIN_PHOTO` / `MISSING_FILL_PHOTO` / `OIL_VERDICT_MISSING` | 维修照片缺失或动作未判定 |
| `RULE_HANDE_DRAIN` / `RULE_HANDE_TIRE` / `RULE_FILTER_UNEXPECTED` | 违反桥型/滤芯规则 |
| `MISSING_SERVICE_VIN` / `SERVICE_VIN_MISMATCH` | 服务单 VIN 缺失或不一致 |
| `MISSING_SIGNATURE` / `MISSING_STAMP` | 缺签字或盖章 |
| `OCR_TIMEOUT` / `OCR_UNAVAILABLE` | OCR 超时或不可用 |
| `TIMEOUT` / `INTERNAL_ERROR` | 分析超时或失败 |
| `OTHER` | 未映射原因，按 `reasons` 处理 |

## 6. 调用示例

```bash
# 接车
curl -X POST http://10.51.13.7:8020/v1/arrival \
  -H "X-Request-Id: order-123-01" \
  -F "images=@plate.jpg" -F "images=@license.jpg" \
  -F "expected_plate=晋K05907D"

# 维修
curl -X POST http://10.51.13.7:8020/v1/repair -F "images=@axle.jpg" -F "axle_type=hande"

# 检查表
curl -X POST http://10.51.13.7:8020/v1/inspection -F "images=@front.jpg" -F "images=@sign.jpg"
```

```bash
# 需要检测框：boxes 是 query 参数（写成 -F boxes=1 不会生效）
curl -X POST "http://10.51.13.7:8020/v1/arrival?boxes=1" -F "images=@plate.jpg"
```

```python
import requests

files = [("images", open(p, "rb")) for p in ["plate.jpg", "license.jpg"]]
r = requests.post("http://10.51.13.7:8020/v1/arrival", files=files,
                  data={"expected_plate": "晋K05907D"}, timeout=40)
d = r.json()
passed = d["result"] == "pass"
```
