## 0. 先说结论

服务本身是好的：识别、OCR、规则、并发控制都在正常工作，单图约 0.5–0.9 秒。
这次反馈的 7 条里，**没有一条是模型精度问题**，全部是产品语义、状态管理和部署配置问题：

| # | 你看到的 | 真正的原因 | 处理 |
|---|---|---|---|
| 1 | 新数据/老数据点了没反应 | 前端选择器少了一个属性，绑定根本没执行；这个切换本身也只改图表、不改 KPI，保留价值低 | 删掉这个切换，首页只展示一套“全部留出数据”的准确率 |
| 1b | 训练集/验证集/测试集在哪、比例多少、怎么人工复核 | 旧训练只做 8:2，且要在服务器跑脚本；上传批次没有独立测试集；人工改标没有进入训练 | 新增“一键准备训练集”：按工单整组切 70/15/15，生成 manifest；改标优先用于训练；训练后自动跑测试集 |
| 2 | 车牌识别成功了，还提示没有 VIN | 聚合逻辑把“没提交行驶证/里程表”当成了“提交了但没识别到” | 区分“未提交 / 未识别到 / 不一致”；单张只判单张，整单才要求四件套齐全 |
| 3 | 数据集不能删、看不到自动标注、不能改标 | 后端只有上传和自动标注，没有详情/删除/人工改标接口 | 新增批次详情、逐张改标、删除批次（级联清理记录） |
| 4 | 快速标注提示 20 张图片不存在，是不是挂载坏了 | 不是挂载问题。是 upload_20261116_140800 这批图被删过，但 SQLite 里的 20 条自动标注记录没删 | 删除批次时级联清理；页面提供“清理失效记录”按钮 |
| 5 | 有没有接口文档，能不能给业务系统/本地验证 | 只有 Swagger，缺少面向业务的字段说明和可直接跑的脚本 | 新增 [SPM图片ai识别API文档.md](SPM图片ai识别API文档.md)，控制台左侧加“接口文档”，保留 /docs 和 /openapi.json |
| 6 | 模型删除失败：服务内部错误 | deploy/docker-compose.yml 把 models/ 以**只读**挂给 api，删目录/写 registry 都会失败 | api 改为可写挂载；删除失败给出明确原因，并支持“仅从列表移除、保留权重” |
| 7 | 首页模型列表太多、口径描述听不懂 | 把所有辅助头都列出来，还用了“折外/场景头/辅助头停用/支持数(n)”这类内部术语 | 默认只显示真正参与判定的两个模型；文案改成人话；去掉“口径”长说明 |

## 1. 上线后的标准流程（以后每次迭代只跑这一遍）

### 1.1 服务器升级：一条命令

在服务器仓库根目录：

~~~bash
git pull
bash deploy/upgrade.sh            # 构建 api + nginx，起服务，等健康检查
# 首次部署或换了 vision/ocr 镜像时：
bash deploy/upgrade.sh --all
~~~

脚本会做：检查 .env / models/current / data/ → docker compose config →
构建 → up -d → 轮询 /healthz → 打印 /v1/meta、/readyz、容器状态。
任何一步失败直接非 0 退出，不会出现“命令成功了但服务没起来”。

> 只改前端也必须重建 api：web/ 是 COPY 进 api 镜像的。
> 只改 deploy/nginx.conf 时，脚本里的 api+nginx 重建同样适用。

### 1.2 新数据进来：上传 → 自动标注 → 人工确认

1. 数据集页上传 zip（zip 内按类别建目录，如 01_桥放油/ 或 bridge_drain/）。
2. 点该批次的「自动标注」，模型给每张图一个预标注和置信度。
3. 点「查看 / 改标」：
   - 每张图显示：目录标签、模型预标注、置信度；
   - 下拉框可直接改成正确类别，或选“无法判断 / 不算这一类”（不进入训练）；
   - 点「保存修改」，人工结论写入 SQLite，立即生效。
4. 不需要的测试批次直接点「删除」，目录、自动标注、人工结论会一起删。

### 1.3 训练：不再登服务器跑脚本

模型版本页 → 训练：

1. 「训练数据」选 **全部历史数据（自动 70/15/15）**，或选某个上传批次。
2. 点「开始训练」。平台会自动：
   - 合并新旧数据；
   - 按内容去重（同一张图重复上传只留一份）；
   - **按工单整组切分**，同一工单的照片不会同时进训练和测试；
   - 生成 data/processed/datasets/<名称>/manifest.json（含每张图的 split、标签、来源、sha256）；
   - 训练完成后在**独立测试集**上评估，写 test.json。
3. 训练完成页面会显示：验证集准确率、**测试集准确率（N 张，未参与训练/调参）**。
4. 确认后点「注册为候选版本」，填版本号（如 v5.2.0）。
5. 到下方模型表点「设为线上」，热加载生效；不需要重启 vision。

> 比例是默认值，也可在接口 POST /viz/api/dataset/build 传 train/val/test 自定义，
> 但三者之和必须为 1。**测试集只用于验收，不能拿来调参。**

### 1.4 上线门禁（建议写进流程）

- 没有独立测试集结果的训练，页面会明确提示“不能作为上线依据”；
- 注册候选版本时会二次确认；
- 切换线上版本前会校验 manifest.json 里每个权重的 sha256，不一致直接拒绝；
- 切换后可回滚到任意历史版本（同样走 sha256 校验）。

## 2. 数据与训练的“标准模式”

### 2.1 切分

| 集合 | 比例 | 用途 |
|---|---|---|
| train | 70% | 训练 |
| val | 15% | 选最佳 epoch（早停） |
| test | 15% | 只做最终验收，不参与调参 |

切分单位是**工单**（文件名里的 IKD...），不是单张图。
同一工单的多张照片一定落在同一个 split，避免“同一辆车既在训练又在测试”。

### 2.2 标注数据在哪

- 原始目录标签：data/raw/recut/...、data/SPM系统AI识别训练照片_新增_...
- 上传批次：data/raw/uploads/<batch>/<slug>/
- 人工确认/改标：var/feedback.sqlite3 的 annotations 表（页面可导出 CSV）
- 训练集清单：data/processed/datasets/<名称>/manifest.json
  - 每张图：split、label、order、origin、sha256、相对路径
  - 顶部：比例、各 split 张数、各类张数、工单数、内容哈希、告警

换机/换挂载点后，训练集目录里的软链是**相对路径**，不需要重建。

### 2.3 人工复核

快速标注页和数据集详情页都可以改标。区别：

- 快速标注：面向评测/难例，按置信度从低到高排队；
- 数据集详情：面向某个上传批次，逐张对照“目录标签 vs 模型预标注”，适合验收新数据。

人工结论优先于目录标签进入训练；选“无法判断/不算这一类”的图会被跳过。

## 3. 部署拓扑与挂载

~~~text
浏览器 → nginx:8020 → api:8017 → vision:8016 (GPU)
                              → ocr:8018
~~~

| 宿主机目录 | api | vision | 说明 |
|---|---|---|---|
| data/ | 读写 | — | 原始照片、上传批次、训练集 |
| docs/ | 只读 | — | 评测报告、标注规范 |
| models/ | **读写** | 只读 | api 要写 registry/current；vision 只读加载 |
| var/ | 读写 | — | SQLite、训练任务、run 输出 |

> 之前 api 的 models 是 :ro，这是“删除模型 500”的唯一原因。
> 现已在 compose 里改为可写；如果服务器上还是旧 compose，请以仓库版本为准。

## 4. 验收清单（上线前逐项打勾）

~~~bash
# 1. 三个探针
curl -s http://127.0.0.1:8020/healthz
curl -s http://127.0.0.1:8020/readyz | jq '{ok,vision,ocr}'
curl -s http://127.0.0.1:8020/v1/meta | jq '{model:.model.configured_version,limits}'

# 2. 单张识别：12 个场景各打一次（200 = 成功，422 = 需重拍）
curl -s -o /tmp/r.json -w '%{http_code}\n' -X POST http://127.0.0.1:8020/v1/recognize \
  -F "scene=arrival_plate" -F "image=@plate.jpg"
cat /tmp/r.json

curl -s -o /tmp/r2.json -w '%{http_code}\n' -X POST http://127.0.0.1:8020/v1/recognize \
  -F "scene=service_sign" -F "image=@sign.jpg"

# 3. URL 输入
curl -s -o /tmp/r3.json -w '%{http_code}\n' -X POST http://127.0.0.1:8020/v1/recognize \
  -F "scene=odometer" -F "image_url=https://<可访问地址>/odometer.jpg"

# 4. 压测：32 并发必须 P95 < 3s
python scripts/bench_api.py --base http://127.0.0.1:8020 \
  --path /v1/recognize --scene arrival_plate \
  --image plate.jpg --vus 32 --requests 320 --max-p95-ms 3000

# 5. 控制台页面（4 页）：识别测试 / 模型版本 / 训练 / 文档
~~~

## 5. 给业务系统的交付物

1. **接口说明**：[docs/SPM图片ai识别API文档.md](SPM图片ai识别API文档.md)
   - 单张 `POST /v1/recognize` + 12 个 `scene`；HTTP 200/422；`scene`/`message`/`data`
   - 文件与 URL 两种输入、各场景字段、可直接复制的 curl。
2. **性能与改造方案**：[docs/reports/final_plan_20261120.md](reports/final_plan_20261120.md)
   - 32 并发 / P95 < 3s 的容量计算、瓶颈定位（OCR）、改造清单与压测方法。
3. **在线调试**：http://<服务器>:8020/docs （Swagger）。
4. **机器可读契约**：http://<服务器>:8020/openapi.json 。
5. **部署自检**：`deploy/verify.sh` 与 `bash deploy/smoke_compose.sh`。

业务判断只需要一条：**HTTP 200 = 识别成功，非 200 = 不成功**；看 `message` 决定是否重拍。

## 6. 这次仍然存在的边界（别当成 bug）

1. **训练默认在 api 容器里跑 CPU**。TRAIN_DEVICE=auto 会自动选 cuda/mps/cpu；
   api 镜像是 CPU 版 torch，所以生产大概率是 CPU，1300 张 25 轮会比较慢。
   如果训练频繁，建议下一步把训练放到 vision 同款 GPU 镜像的一次性 trainer 容器，
   推理和训练隔离；这需要改 compose 和训练入口，属于下一阶段。
2. **vision 镜像必须在 Linux + NVIDIA 上构建**，macOS 无法构建 CUDA 基础镜像。
   首次部署请在服务器上执行 deploy/upgrade.sh --all。
3. **单副本**：SQLite、限流、准入、训练任务状态都是进程内/单机状态。
   当前 api 已改为单 worker，保证这些状态一致；如果要水平扩展，先把反馈库迁到 PostgreSQL。
4. **v5.0.0 的 95.33% 与 v5.1.0 的 87.09% 不可直接比较**：评测集不同。
   新流程统一用独立测试集，页面上会标注“旧评测集”，不再用“不可比”这种内部词。
5. 线上服务器当前仍跑旧镜像；**需要在服务器执行一次 bash deploy/upgrade.sh**，
   本文和代码里的修复才会生效。

## 7. 一句话总结

以后只有三个动作：

1. 服务器：bash deploy/upgrade.sh
2. 数据：上传 → 自动标注 → 人工改标 → 准备训练集
3. 模型：训练 → 看测试集 → 注册候选 → 设为线上（可回滚）

不需要再登服务器手工跑 build_union.py，不需要再猜“这个数字是什么口径”，
也不会再出现“删不掉、点不动、提示误导”的情况。
